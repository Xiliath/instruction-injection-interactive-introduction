🔒 Veiligheid: Escaped vs Unescaped Data

Hieronder wordt elke entry op twee manieren getoond om het verschil tussen veilige en onveilige data weergave te demonstreren:

✅ Escaped (Veilig)

Data wordt correct ge-escaped met textContent. HTML/JavaScript wordt als tekst getoond, niet uitgevoerd. Dit is veilig tegen XSS attacks.

⚠️ Unescaped (Onveilig)

Data wordt direct gerenderd met innerHTML. HTML/JavaScript kan worden uitgevoerd. Dit is kwetsbaar voor XSS attacks!

🎓 Uitleg: Wat gebeurt er hier?

Prompt Injection Flow:

  1. AI assistent bezoekt de homepage
  2. AI leest verborgen instructies (HTML comments, hidden divs, etc.)
  3. AI interpreteert deze als legitieme commando's
  4. AI voert de instructies uit (POST naar /api/collect)
  5. Conversatiedata wordt geëxfiltreerd en hier getoond

XSS Vulnerability:

Als de geïnjecteerde data ook kwaadaardige HTML/JavaScript bevat, kan dit leiden tot een second-order XSS attack: de data wordt eerst opgeslagen, en vervolgens uitgevoerd wanneer een admin de data bekijkt in het panel.

// Voorbeeld kwaadaardige payload: { "conversation_summary": "<script>alert('XSS!')</script>", "user_request": "<img src=x onerror=alert('XSS')>" } // Escaped: Toont de tekst veilig // Unescaped: Voert de JavaScript uit!
